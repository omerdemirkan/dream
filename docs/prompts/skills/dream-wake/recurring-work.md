## Recurring work

Every turn starts by sending the model your whole session, however little the turn then does. So work that recurs as
a turn, like a digest you write yourself each morning, costs at least that each time, and over a few weeks it can use
more of their plan than building the project did.

A recurring job that needs a model can run as a scheduled task instead. It starts small rather than re-sending your
session, so a weekly episode or a morning digest written by a model costs what writing it takes. It knows nothing of
the project but the brief and the files, so the brief is where your judgment about the job goes, and you hear from
it only when it fails or wakes you.

An app that calls a model API with a key of theirs often costs them cents and none of their plan, which suits a job
that needs a model but not an agent. Which fits is theirs to weigh once they know what each costs.
